ATT&CK Pair Forecasting Study

Can a shared-neighbour graph forecaster predict which MITRE ATT&CK techniques will next be documented together, better than knowing how common each technique is?

2026-11-183 splits × 3 edge sets · 8 methodsCode: github.com/rishab2114/graph

Verdict

  1. Popularity explains most of it. A baseline that ranks pairs by freq(u)·freq(v) reaches an AUC of 0.72–0.79 in every setting.
  2. Supervised graph models do not transfer across time. Logistic regression on all features beats that baseline in 1 of 9 settings. Gradient boosting does so in 0 of 9.
  3. Structure carries a small signal at fixed popularity. Within popularity deciles, the untrained structural score beats frequency in 9 of 9 settings.
  4. An exploratory blend gains up to +0.027 AUC but loses at the top of the list. Its precision at 100 is lower than frequency in 8 of 9 settings. It was designed after seeing the data, so a prospective test is pre-registered.

Design

Each ATT&CK Enterprise release becomes a graph. Nodes are parent techniques (sub-techniques are collapsed). An edge joins two techniques used by the same intrusion set, campaign, malware or tool. Revoked and deprecated objects are dropped. For a cutoff release T, the candidates are all unlinked pairs at T. The positives are pairs newly documented together by a release two years later.

Supervised models train on the previous two-year window (graph at T−2y, labels at T). They never see the test release. Every method except one was fixed before any multi-split result was seen.

Why the bridge idea is weak here

In the research-concept graphs this method came from, there are about 123,000 concepts and most pairs are far apart, so a pair with a few shared neighbours is unusual and informative. ATT&CK has only about 180 parent techniques, and 49%–66% of all pairs are already linked. Almost every unlinked pair is bridged many times over, so shared-neighbour counts mostly restate popularity.

Using a sparser edge set (malware and tools only, density about 0.5) gave structure less of an edge, not more.

Threats to validity

  • The target is MITRE's documentation, not attacker behaviour. Many new edges document old activity.
  • S2 overlaps S1 and S3 in time, so the nine settings show robustness but are not nine independent replications.
  • The test windows have now been looked at. Only the pre-registered test can confirm the exploratory blend.
  • One data source. Fraud typologies may behave differently.

Pre-registered prospective test

Fixed in PREREGISTRATION.md on 2026-11-18, before the data exists. Graph at ATT&CK-v20.1; outcome is the first Enterprise release dated on or after 2027-10-01; edge set all; code frozen at that commit.

  • H1: the blend's AUC beats frequency (95% paired-bootstrap lower bound above 0).
  • H2: within popularity deciles, the structural score beats frequency.
  • H3, expected null: no supervised model beats frequency.
  • Precision at 100 is reported for every method whatever the outcome.

What this is, and what it is not

This is a careful, reproducible negative result with a sound evaluation method: leakage-controlled time-travel splits, a popularity-stratified AUC that separates structure from popularity, paired confidence intervals, and a pre-registered prospective test. That is a solid workshop paper, technical blog post or portfolio project.

It is not yet a major research contribution. The project's central question has not been tested: whether invented scenarios predict how fraud or intrusion detectors perform on a later, untouched period (experiments E3 and E4). That needs a dated, labelled holdout from the same domain as the graph. It also needs the prior-work search the plan calls for.

Next steps

  • Choose the holdout dataset and domain (Phase 0). The graph source must match it.
  • For scenario selection, rank by popularity and use structure only to re-rank inside a popularity band, where the signal is.
  • Run the prior-work search: SynthAML, studies of stress-test transfer, hyperbolic link forecasting.
  • Rerun python -m gffs.study when the pre-registered outcome release appears.
