# E1 result: forecasting pairs newly documented together (ATT&CK Enterprise)

Run: `python -m gffs.e1 --config config/releases.toml --out results/` (raw output in `results/e1.json`).

| | Release | Date (latest `modified`) |
|---|---|---|
| train_from | ATT&CK-v8.0 | 2020-10-27 |
| train_to = cutoff T | ATT&CK-v12.0 | 2022-10-24 |
| test_to | ATT&CK-v16.0 | 2024-10-28 |

Candidates at T: **5,529** unlinked technique pairs (180 parent techniques). Positives, meaning pairs
newly documented together by v16.0: **729** (13.2%).

| Method | AUC | Precision@100 |
|---|---|---|
| Shared-neighbour forecaster (logistic regression, trained v8→v12) | 0.669 | 0.19 |
| **Frequency-matched baseline** (freq(u)·freq(v)) | **0.728** | **0.45** |
| Uniform random | 0.499 | 0.10 |

## Answer to sub-question 1

**No.** The forecaster beats uniform random but **loses to the frequency-matched baseline** on both
metrics. Following spec §5: on this data, how common a technique is explains all of the gain
over random, and more.

## Why (diagnostics, not used for model selection)

- **The graph is dense.** At T, 66% of all technique pairs are already linked (v8: 60%, v16: 64%).
  In a graph this dense, "shared neighbours" is close to a measure of popularity, so the bridge
  signal the method relies on (spec: "far apart but with a few bridges") hardly exists.
- **The learned combination does worse than its own inputs.** On the test window, single features
  score AUCs of 0.70–0.74 (`weighted_cn` 0.743, `resource_allocation` 0.737, `freq_min` 0.729).
  The fitted model reaches only 0.669, and only 0.701 even on its own training window. The
  coefficients learned on v8→v12 do not transfer to v12→v16.
- Picking `weighted_cn` now *because* it scored best on the test window would be leakage. A fair
  follow-up selects features or models on the training window only. Candidates: rank averaging,
  a single feature chosen on v8→v12, or gradient boosting.

## Caveats

- Positives are pairs **newly documented together by MITRE**, and many are backfill of older
  activity (review note 5). This measures how well we predict the catalogue, not attackers.
- One split only. Repeat with T = v14.0 and T = v16.0 → v20.0 (released 2026-10-13) before
  drawing conclusions.
- Edges come from intrusion sets, software and campaigns combined. A sparser edge definition,
  such as campaigns only, might restore the bridge signal. That is worth testing as a pre-registered variant.
