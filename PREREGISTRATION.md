# Pre-registration: prospective test of technique-pair forecasting on ATT&CK

Written 2026-11-18, before any ATT&CK Enterprise release later than **v20.1** existed.
The commit that adds this file is the timestamp. Do not edit this file after that commit.
Record deviations in a separate file.

## Why this exists

All test windows available today (v16.0, v18.0, v20.0) were used in the multi-split study
(`docs/results/study.md`). The method `hybrid_rank_exploratory` was designed **after** those
results were seen, so its apparent gain is exploratory. The only clean test left is data that
does not exist yet.

## Fixed design

| Item | Value |
|---|---|
| Graph at cutoff T | `ATT&CK-v20.1` Enterprise bundle from `mitre/cti` |
| Outcome release | the first Enterprise release whose latest object `modified` date is **on or after 2027-10-01** |
| Edge set | `all` (intrusion-set, malware, tool, campaign), parsed by `gffs.attack.technique_sets` at this commit |
| Candidates | `candidate_pairs(G_T)`. Positives: `new_edges(G_T, G_outcome)` |
| Code | `gffs` at the commit that adds this file. No changes to features, models or metrics |

## Hypotheses

- **H1 (primary).** `hybrid_rank_exploratory` has a higher AUC than the `frequency` baseline.
  Test: paired bootstrap (1,000 resamples, seed 0). H1 is supported if the lower end of the 95%
  interval is above 0.
- **H2.** Within popularity deciles, `structural_rank_mean` has a higher stratified AUC than
  `frequency`.
- **H3 (expected null).** No supervised model (`logreg_all`, `hgb_all`) beats `frequency` on AUC
  with a 95% interval above 0.
- **Reported regardless of outcome:** precision@100 for every method. The exploratory results
  suggest the hybrid may *lose* at the top of the ranking even if H1 holds.

## What would change our conclusions

If H1 fails, the claim that structure adds value over popularity in ATT&CK is withdrawn. If H1
holds but precision@100 is lower than frequency, the method is not useful for picking a short
list of stress-test scenarios. That is the project's actual use case.
